### Secret 값 수정하는 법 (매번 헷갈리는 부분)

GitHub Secrets는 **기존 값을 조회할 수 없음** (보안 정책). "수정"이 아니라 항상 "새 값으로 덮어쓰기".

1. `Settings → Secrets and variables → Actions`
2. 해당 Secret 이름 클릭 (예: `MAIL_TO`)
3. 빈 입력창에 **새 값 전체**를 다시 입력 (기존 값 이어붙이기 아님, 통째로 새로 씀)
4. `Update secret` 클릭

메일 수신자 추가 예시: `MAIL_TO` 값을 `주소1@x.com,주소2@x.com` 형태로 전체 재입력.

## 3. 실행 방법

### 자동 실행
`.github/workflows/daily.yml` 설정: **매주 월~금 KST 08:00** 자동 실행 (주말 제외)

### 수동 즉시 실행
1. 정확한 주소로 이동 (Actions 탭에서 헤매지 말고 바로 여기로):
   ```
   https://github.com/everwise-lim/arania-intel/actions/workflows/daily.yml
   ```
2. 우측 `Run workflow ▾` 클릭 → 다시 초록 `Run workflow` 클릭
3. 10~15분 소요 (Google News 호출 간격 1.5초씩 넣어서 시간 걸림)
4. 완료되면 메일 도착

### 실행 전 필수 확인 (한 번만 설정하면 됨)
`Settings → Actions → General → Workflow permissions`
→ **`Read and write permissions`** 선택돼 있어야 함. 안 그러면 마지막 단계(`git push`)에서 403 에러로 실패.

## 5. 스코어링 로직 요약

```
score = 영향도(1~3) × 확실성(0.4~1.0) × 등급배수(S1.8/A1.4/B1.0/C0.7/D0.5) × 보도확산(1.0~1.3)

긴급(URGENT)  : score ≥ 5.0   → 즉시 메일 상단
브리프(DAILY) : score ≥ 3.0   → 브리프 수록
그 외         : 폐기

신용리스크·계약분쟁·아티스트리스크는 거래처가 S·A등급이면 점수 무관하게 무조건 긴급 처리
```

거래처당 최대 3건, 긴급 최대 15건, 브리프 최대 40건으로 상한을 둠 (과다 노출 방지).

## 6. 매칭 규칙 (오탐 방지 핵심)

- **매칭 실패 기사는 폐기** — 검색을 유발한 회사에 임의로 배정하지 않음
- **회사명이 아티스트명보다 항상 우선** — "세븐틴 키운 한성수가 만든 하이브 신인" 같은 문장에서 수식어(세븐틴)가 아니라 주체(하이브)를 채택
- **플랫폼명 매칭 제외** — Weverse·멜론·지니 등은 기사 출처일 뿐이므로 거래처로 오인하지 않도록 차단
- 앞 글자가 한글이면 다른 단어의 일부로 보고 기각 (부분일치 오탐 차단)
- 아티스트명은 `companies.csv`의 로스터확신도가 **"높음"**인 것만 매칭 근거로 사용

## 7. 거래처 마스터 수정 시 주의점

`config/companies.csv`를 GitHub 웹에서 직접 편집할 때:
1. 파일 클릭 → 연필(Edit) 아이콘
2. **별칭** 열이 뉴스 매칭 정확도의 핵심 — 언론이 실제 쓰는 표기를 `|`로 구분해 모두 기입
   예: `쏘스뮤직|SOURCE MUSIC|소스뮤직`
3. **대표아티스트_초안**과 **로스터확신도**를 같이 채워야 아티스트명이 매칭에 쓰임 (확신도가 "높음"이어야 함)
4. 수정 후 Commit → 다음 실행부터 반영

현재 최우선 과제: 계열그룹 "확인필요" 102개사 중 S·A등급 21개사를 국세청 홈택스 사업자등록 상태조회로 확정.

## 8. 자주 겪은 문제와 해결책 (트러블슈팅 로그)

| 증상 | 원인 | 해결 |
|---|---|---|
| Actions 목록에 워크플로가 안 뜸 | YAML 파일에 마크다운 표시(```yaml)가 같이 붙어 들어감 | 파일 첫 줄이 `name:`으로 바로 시작해야 함, 백틱 절대 포함 금지 |
| `Run workflow` 버튼이 안 보임 | 화면 폭 문제로 Actions 탭이 상단 메뉴에서 숨겨짐 | `.../actions/workflows/daily.yml` 주소로 직접 접속 |
| 실행은 되는데 마지막에 실패(403) | Workflow permissions가 read-only로 되어 있음 | `Settings → Actions → General → Read and write permissions`로 변경 |
| 무관한 기사가 대량으로 잡힘(171건) | 매칭 실패 시 검색 유발 회사에 강제 배정하던 폴백 로직 | v3에서 폐기 처리로 변경, 문맥 게이트(필수/배제 키워드) 추가 |
| 같은 뉴스가 수십 건 중복 노출 | 매체별로 제목이 조금씩 다른 기사를 별개로 처리 | 문자 3-gram 유사도 기반 군집화 도입 |
| 수식어가 주체로 오인됨 (세븐틴→플레디스 등) | 아티스트명과 회사명을 동일 우선순위로 매칭 | 회사명 우선 2단계 매칭으로 변경 |
| `.github` 폴더가 업로드 시 안 보임 | OS 탐색기가 점(.)으로 시작하는 폴더를 숨김 처리 | GitHub에서 `Add file → Create new file`로 `.github/workflows/daily.yml` 경로를 직접 입력해 생성 |
| Google News 503 에러 다발 | 연속 호출 시 요청 제한 | 1.5초 간격 + 지수 백오프 추가 (실행시간은 늘어남, 대신 안정적) |
